# Motwi M3: App and Main Window Implementation Plan

> Executed inline by the orchestrator (owner's instruction), one commit per task, one review at the end.

**Goal:** Double-click Motwi, finish a guided setup without a terminal, and manage everything from a native window. Motwi keeps running in the tray when the window closes.

**Architecture:**
- `motwi.service.Motwi` is the long-lived supervisor. It owns the store, the live config, one event bus, the Twitch session (restartable), sign-in flows, AI keys, "Try a message" and the stats queries. Nothing in it is UI-specific.
- `motwi.api` is an aiohttp server on `127.0.0.1` that exposes the service as JSON over HTTP, plus one WebSocket of events. It serves the built UI.
- `motwi.desktop` runs the service and server on an asyncio thread, opens a pywebview (WebView2) window on the main thread, and shows a pystray tray icon.
- `ui/` is a Svelte 5 + TypeScript + Vite app. It builds to `ui/dist`, which the server serves.

**Tech Stack:** M2, plus `aiohttp` (server), `pywebview`, `pystray` and `Pillow`. UI: Svelte 5, Vite, TypeScript, `@fontsource/inter`, `@fontsource/jetbrains-mono`, `@phosphor-icons/core`.

**Spec:** `docs/superpowers/specs/2026-10-27-motwi-design.md`, sections 2 (anti-goals), 4, 5.5, 5.6, 6.2, 6.3, 6.4 and 7.

## Global Constraints

- The server binds `127.0.0.1` only. Default port 47815, overridable with `MOTWI_PORT`.
- Every `/api` request carries `Authorization: Bearer <token>`. The WebSocket authenticates with its first frame, `{"type": "hello", "token": ...}`, within 5 s.
- The window's token is random per launch and reaches the UI in the URL fragment (`#k=`), which never goes to a server or a log.
- Requests whose `Host` is not `127.0.0.1:<port>` or `localhost:<port>` get 403 (DNS rebinding). No CORS headers in M3. The extension origin is added in M4.
- One save model everywhere: a change saves when it is committed (toggle flipped, option picked, field left or Enter pressed). Each field shows its own Saving / Saved / error state. There is no Save button.
- Every view has real empty, loading and error states.
- Visual language from spec 6.4: dark surfaces `#131316` / `#18181b`, lines `#2a2a30` / `#2f2f35`, accent `#4fd1b5`, action colors deleted `#3987e5`, warned `#c98500`, timeout `#d95926`, ban `#d55181`. Inter and JetBrains Mono, self-hosted. Phosphor icons. Radius 6 px panels and inputs, 4 px chips and buttons.
- Accessibility: real labels, named icon buttons, visible focus, AA contrast, `aria-live` for status and ban requests, reduced motion.

## Decisions

- **Accounts and AI in the app.** Provider and model live in `Settings.primary` / `Settings.backup`. Keys stay in Credential Manager (`ai:primary`, `ai:backup`). `MOTWI_AI_KEY` still wins when set. Missing keys don't block Twitch: blocked words and the spam filter keep working, and the status says the AI is off.
- **Engine states.** `stopped` (no account or setup unfinished), `connecting`, `watching`, `suggesting`, `paused` (the on/off switch; chat is not processed but the connection stays up), `reconnect` (Twitch sign-in expired; no retry loop).
- **New settings.** `setup_complete` (false until the setup's last step), `delete_on_warn` (true; spec 5.3 builder's call), `paused` (false).
- **New tables.**
  - `streams(id, started_at, ended_at, title, game)`, written on `stream.online` / `offline` and at connect if live. It powers the "last stream" range and the M5 recap.
  - `message_counts(day, stream_id, checked)`, the number of non-exempt messages Motwi checked. Kept in memory and flushed every 30 s, so chat doesn't cause a write per message.
  - `blocked_words.hidden`: hidden phrases (slurs) collapse behind a count in the UI.
- **Retry.** A failed action can be retried. It re-runs the same plan as the same actor.
- **Try a message.** Blocked words first, then the real model with the real rules and stream context, then the decision engine with no prior offenses. It never acts, and it doesn't move the AI state or circuit breaker. Usage is recorded, since it costs money.
- **People → banned.** Helix "Get Banned Users" as the streamer (it requires the broadcaster's token). Unban from there is a plain Helix unban.
- **Mods screen.** M6 builds it. Until then it explains that mods can moderate through Twitch and that invites are coming.
- **Extension step in setup.** M4 fills it in. Until then the step says the extension is coming and can be skipped.
- **Launch.** `motwi` with no arguments opens the app. A GUI script `motwi-app` opens it without a console. `motwi run` stays headless. A second launch focuses the running window (`POST /api/show` with header `X-Motwi: 1`, which a web page cannot send without a CORS preflight).

## API

| Method and path | Purpose |
|---|---|
| `GET /api/status` | setup, Twitch accounts and state, stream, engine state, AI state and providers, month cost |
| `POST /api/engine` `{paused}` | the on/off switch |
| `GET`, `PATCH /api/settings` | editable fields only; 422 `{field, message}` |
| `GET /api/rules`, `POST`, `PATCH /{id}`, `DELETE /{id}` | rules |
| `GET /api/blocked`, `POST`, `DELETE /{id}` | blocked words |
| `GET /api/people`, `POST`, `DELETE /{kind}/{login}` | trusted, VIP, recently actioned |
| `GET /api/banned`, `POST /api/unban` | banned and timed-out chatters |
| `GET /api/actions?kind&status&rule&user&stream&actor&q&before&limit` | history |
| `POST /api/actions/{id}/{approve,deny,undo,retry}` | action buttons |
| `GET /api/stats?range=stream,7d,30d` | stats |
| `GET /api/overview` | today's numbers, open ban requests, warnings |
| `POST /api/try` `{text}` | try a message |
| `POST /api/twitch/login` `{role}`, `POST /api/twitch/logout` `{role}` | device code sign-in; the result arrives on the WebSocket |
| `GET /api/ai`, `PUT /api/ai/{slot}`, `DELETE /api/ai/backup`, `POST /api/ai/test` | providers, keys, Test |
| `WS /api/events` | `status`, `action`, `reminder`, `login` events |

## Tasks

1. **Service layer.** Store additions (migration 3, stats and history queries, streams, message counts), settings additions, `Scorer.reset_clients` and `try_score`, `ModerationService.retry`, `HelixClient.banned_users`, `MotwiApp` taking a shared bus and a paused flag, and `motwi.service.Motwi`. Tests with a fake Twitch.
2. **Local API.** `motwi.api`: auth, Host checks, routes, WebSocket, static UI. Tests with aiohttp's test client.
3. **Desktop shell.** `motwi.desktop`: asyncio thread, pywebview window that hides on close, tray icon (Open, Pause/Resume, Quit), single instance, `motwi` default command and `motwi-app` GUI script.
4. **UI shell.** Vite + Svelte 5 + TS scaffold, design tokens, fonts, icons, rail with the status block, router, API client and event store, shared states (loading, empty, error), toast-free per-field save feedback.
5. **Setup flow.** Spec 6.3. Each step checks for real before moving on.
6. **Screens.** Overview, Rules (with Try a message), History, People, Stats (stacked bars with tooltips and a table view), Settings, Mods placeholder.
7. **CI and docs.** UI build and type check in CI. The server test uses a stub `ui/dist`. README: run the app.

## Review Focus

- The window token never appears in a log line or a query string.
- A Twitch sign-in that expires while running flips the state to `reconnect` and stops. It doesn't loop.
- Closing the window keeps moderation running. Quit stops it cleanly, with in-flight messages drained.
- Changing the AI key or provider while running takes effect on the next batch without a restart.
- History and stats stay correct across a stream boundary and a midnight boundary (local time).
